5.5. Decimal Handling Specification (CRITICAL)
This is a critical integration point that must be handled correctly.
Hedera (HBAR) Native: 8 decimals (tinybar).
EVM (via JSON-RPC): 18 decimals (weibar).
StakeIt.sol Contract: The provided stake_it.sol (Source 1-63) defines constants using 8 decimals (e.g., MIN_STAKE = 1 * 10**8).
Resolution (Mandatory Requirement):
The StakeIt.sol contract must be refactored to use 18 decimals exclusively to be compatible with the EVM tooling ecosystem (Ethers.js).
All constants must be updated:
MIN_STAKE becomes 1 * 10**18
MAX_STAKE becomes 100 * 10**18
VOTER_STAKE becomes 1 * 10**18 (or 1 * 10**17 for 0.1 HBAR, etc.)
The frontend team must be aware of this. When using HashPack (which uses 8 decimals), the value must be scaled up to 18 decimals before being sent to the contract. (e.g., 1 HBAR -> 1 * 10**18). This ensures the contract only ever "sees" 18-decimal values, regardless of the user's wallet.
