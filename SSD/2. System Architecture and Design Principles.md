## 2.1. The Web3 Architectural Blueprint

### Presentation Layer (Frontend)

A responsive web application built in React (or Next.js).

- Communicates with wallets via HashConnect (for HashPack).
- Communicates with the smart contract via JSON-RPC.
- Communicates with the off-chain cache/backend via REST/GraphQL API.

### Business Logic Layer (On-Chain)

- **Hedera Smart Contract Service (HSCS)**: Hosts the StakeIt.sol EVM-compatible smart contract, which governs all funds, stakes, and core logic.

### Data Layer (Hybrid)

- **On-Chain Data**: (See [2.2](#22-on-chain-vs-off-chain-data-strategy)) All financial states, goal states, roles, and vote data stored within the StakeIt.sol contract.
- **Off-Chain Data (Decentralized)**: User-submitted proofs (images, videos) will be stored on IPFS. The resulting CID is timestamped on HCS.

### Infrastructure & Interfaces

- **Blockchain**: Hedera Network.
- **Consensus**: Hedera Consensus Service (HCS) for immutable proof timestamping.
## 2.2. On-Chain vs. Off-Chain Data Strategy

### On-Chain Data (Managed by StakeIt.sol)

- **Goal Struct**: `creator`, `stake`, `duration`, `startTime`, `isFinalized`, `isCompleted`.
- **Role Management**: `ADMIN_ROLE` addresses.
- **Treasury**: `charityWallet`, `platformWallet`, `liquidityReserve` addresses.
- **Economic State**: `withdrawable` balances (for Goals/Voters), `voterStakes`, `userPoints`.
- **Vote Data**: `voterVoteBitmask` (a compact mapping to store daily votes).

### Off-Chain Data (Managed by IPFS/HCS)

- **User Proofs**: All images, text, or videos submitted by users. Stored on IPFS to reduce cost and ensure verifiability.
- **Proof Metadata**: The IPFS CID and HCS timestamp for every submitted proof.
## 2.3. Hedera Network and Service Integration

### Hedera Smart Contract Service (HSCS)

The core StakeIt.sol contract will be deployed on the HSCS, leveraging its EVM compatibility and low, predictable gas fees.

### Hedera Consensus Service (HCS)

Used for proof-of-action. When a user submits a proof (see [Journey 3: Daily Proof Submission & Timestamping](SSD/1.%20Foundational%20Project%20Specification.md#journey-3-daily-proof-submission--timestamping)), the proof's IPFS CID is submitted to a dedicated HCS topic. This creates a low-cost, immutable, and provably-fair timestamp before verification begins.

### Hedera Token Service (HTS)

All stakes (Goal and Voter) will use Hedera's native HBAR token.

**Future**: The `userPoints` system will be upgraded to an HTS token to create a tradable, on-chain reward.

### On-Chain Vote Aggregation

Votes are cast on-chain and aggregated automatically within the smart contract for goal finalization, eliminating the need for off-chain oracles.
