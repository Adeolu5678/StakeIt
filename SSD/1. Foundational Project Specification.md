Part I: Foundational Project Specification
1.1. Introduction and Document Purpose
This document constitutes the definitive Software Specification Document (SSD) for the StakeIt Web3 application. It is the single source of truth for all functional and non-functional requirements, architectural designs, and system constraints for the Minimum Viable Product (MVP).
Project Vision:
To solve the widespread problem of goal abandonment by creating a Web3 platform that turns personal goals into a financial commitment. StakeIt leverages Hedera's smart contracts and consensus service to build a transparent, fair, and rewarding accountability system. When users fail, their forfeited stake is automatically donated to a transparent charity pool, turning personal setbacks into social good.
Business Requirements:
Provide Real Accountability: Users must stake real financial value (HBAR) on their personal goals, creating a tangible consequence for quitting.
Incentivize Consistency: Users who successfully complete their goals must have their full stake returned.
Generate Social Impact: A portion of stakes from failed goals must be automatically and transparently distributed to a designated charity wallet.
Foster Community: Enable community participation through a peer-to-peer verification system.
Ensure Trust & Transparency: All staking, penalties, and fund distributions must be handled by an on-chain smart contract, visible to all.
Target Audience:
This SSD is intended for all project stakeholders, including developers, QA engineers, project managers, and business stakeholders, to ensure alignment throughout the project lifecycle.
1.2. User Personas and Decentralized Journeys
User Personas
P1: The Goal-Setter ("David")
Description: A young professional who struggles with consistency for personal goals (e.g., fitness, learning a new skill).
Needs: External motivation, a "skin in the game" mechanism to stay on track.
Web3-Readiness: Familiar with crypto basics; owns HBAR and uses a HashPack or MetaMask wallet.
P2: The Verifier ("Amina")
Description: An active community member who enjoys participating in Web3 ecosystems.
Needs: A way to contribute to the community, a mechanism to earn small rewards or points for their time.
Web3-Readiness: Actively uses dApps and is willing to stake small amounts to participate in protocols.
P3: The Admin (Role)
Description: The StakeIt core team, responsible for initial contract deployment and configuration.
Needs: Ability to manage critical contract parameters and pause the system in an emergency.
P4: The Oracle (System)
Description: An automated, off-chain service that monitors goals.
Needs: A secure private key (ORACLE_ROLE) to submit finalized goal results to the smart contract.
Decentralized Journeys (MVP Use Cases)
Journey 1: User Onboarding & Authentication
Actors: Goal-Setter, Verifier
Flow:
User visits the StakeIt web application.
User clicks "Connect Wallet."
A modal appears offering "HashPack" and "MetaMask."
User selects their wallet and approves the connection in the wallet extension.
The UI updates to show the user's truncated wallet address and HBAR balance.
Journey 2: Goal Creation & Staking
Actors: Goal-Setter, Wallet, Smart Contract
Flow:
User navigates to the "Create Goal" page.
User fills out a form:
Title: (e.g., "Work out daily")
Duration: (Slider/input, must be 7-30 days)
Stake Amount (HBAR): (Input, must be 1-100 HBAR)
Frontend validates inputs against contract constants (MIN/MAX_DURATION, MIN/MAX_STAKE).
User clicks "Stake My Goal."
Frontend calls the createGoal() function, sending the Stake Amount as msg.value.
The user's wallet prompts them to confirm the transaction (stake + gas).
Upon confirmation, the contract creates the Goal struct, stores the stake, and emits the GoalCreated event.
The user is redirected to their Dashboard, where the new goal appears as "Ongoing."
Journey 3: Daily Proof Submission & Timestamping
Actors: Goal-Setter, Frontend, IPFS, Hedera Consensus Service (HCS)
Flow:
User navigates to their "Ongoing" goal on the Dashboard.
The UI shows a "Submit Proof for Day X" button.
User clicks and uploads proof (image or text).
[Off-Chain] The frontend uploads the proof file to IPFS, receiving a CID (Content Identifier).
[Off-Chain] The frontend submits a message containing { goalId, day, proofCid } to a dedicated HCS Topic. This provides an immutable, verifiable timestamp.
[Off-Chain] A separate backend service listens to this HCS topic and stores the proof metadata in a cache database for easy retrieval by Verifiers.
The UI updates to show "Proof Submitted for Day X - Awaiting Verification."
Journey 4: Daily Verification & Voting
Actors: Verifier, Wallet, Smart Contract
Flow:
Verifier navigates to the "Verify Goals" page.
Verifier sees a list of proofs awaiting verification (pulled from the off-chain cache).
Verifier clicks on a proof, views the image/text, and clicks "Vote."
A modal appears: "Vote 'Yes' (Valid)" or "Vote 'No' (Invalid)."
Upon selection, the frontend calls the castVote(goalId, day, bool) function, sending the VOTER_STAKE (e.g., 1 HBAR) as msg.value.
The user's wallet prompts for confirmation.
The contract validates the vote (user hasn't voted, VOTER_STAKE is correct, etc.), stores the vote, awards VOTE_POINT to the Verifier, and emits VoteCast.
The proof is removed from the Verifier's queue.
Journey 5: Goal Finalization (Automated)
Actors: Oracle, Smart Contract
Flow:
A Goal's duration expires.
[Off-Chain] The Oracle service queries the cache database for all votes associated with that goalId.
[Off-Chain] The Oracle computes the final status:
It creates a tallyPayload (a bitmask representing success/failure for each day).
It determines isCompleted (e.g., >80% of days were successful).
[Off-Chain] The Oracle signs this attestation (goalId, tallyPayload, isCompleted) using its ORACLE_ROLE private key.
The Oracle calls the finalizeGoal(...) function on the smart contract with the payload and signature.
[On-Chain] The contract verifies the Oracle's signature.
Path A (Success): If isCompleted == true, the contract adds the full stake to the Goal-Setter's withdrawable balance and awards COMLETION_POINT.
Path B (Failure): If isCompleted == false, the contract calls _distributeFailure:
Calculates the 25% PENALTY_PERCENT.
Transfers penalty funds to charityWallet, platformWallet, and liquidityReserve.
Adds the remaining 75% of the stake to the Goal-Setter's withdrawable balance.
The contract emits GoalFinalized and FundsDistributed (if failed).
Journey 6: Fund Withdrawal
Actors: Goal-Setter, Verifier
Flow:
User (Goal-Setter or Verifier) has a non-zero balance in the withdrawable mapping (from a completed goal or refunded vote stake).
The UI displays this "Available to Withdraw" balance.
User clicks "Withdraw."
Frontend calls the withdraw() function.
The contract transfers the full withdrawable amount to the user's wallet (msg.sender) and emits Withdrawn.
Journey 7: Voter Stake Refund
Actors: Verifier
Flow:
A goal that the Verifier voted on has been finalized (Journey 5).
User navigates to their Dashboard and sees a "Claim Refunds" button.
User clicks, and the frontend calls refundVoterStake(goalId) for each eligible goal.
The contract transfers the VOTER_STAKE back to the user's wallet and emits StakeRefunded.
(Note: This can be optimized into a batch function later.)
1.3. System Scope and Core Value Proposition
Core Value Proposition:
StakeIt provides Web3-powered accountability. It turns personal goals into financial commitments and transforms failure into social good, all on a transparent and low-fee public ledger.
In Scope (MVP):
User Authentication: HashPack and MetaMask wallet connection.
Goal Creation: Set goal, duration, and HBAR stake.
Daily Verification: User-submitted proofs (image/text) and peer-to-peer voting.
Voting System: On-chain vote casting with a small HBAR stake (VOTER_STAKE).
Smart Contract Logic: All logic for staking, penalties (25%), refunds, and distribution.
Dashboard UI: Simple display of goals, progress, stake, and verification status.
Out of Scope (Future Versions):
AI-powered proof verification.
DAO-based governance for contract parameters.
NFT rewards for goal completion.
Social features (feeds, comments, user profiles).
HTS-based "Points" token.
